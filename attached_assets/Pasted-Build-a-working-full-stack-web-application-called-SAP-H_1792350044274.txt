Build a working full-stack web application called “SAP–HFIR Inspection Round Coordination Portal.”, supporting Dot net project and accessible on mobile phone

## 1. Business context

SAP generates maintenance work orders exported as XML files. Honeywell Forge Inspection Rounds (HFIR) contains existing inspection round templates, and operators use HFIR to schedule and execute field inspection rounds.

This custom application coordinates SAP work orders and HFIR rounds through manual template mapping, operator notification, transaction history, and visibility of round execution results.

The operational workflow is:

1. A user imports SAP work order XML into this application.
2. The application displays the imported work orders.
3. The user manually selects an existing HFIR round template from a searchable dropdown and assigns an operator.
4. The user submits the mapping.
5. The assigned operator receives a notification containing the SAP work order number and selected HFIR round template.
6. The operator opens HFIR separately, manually schedules the round, and manually enters the SAP work order number into that round.
7. The operator executes the round in HFIR.
8. This application retrieves or imports available HFIR round results and displays them against the corresponding SAP work order.

Submitting a mapping must not automatically create, schedule, execute, or approve a round in HFIR.

## 7. HFIR round results and statuses

Create a “HFIR Round Tracking” page displaying round executions associated with SAP work orders.

Support these five requested business status labels:

- Approved.
- Rejected.
- Successful.
- Incomplete.
- Overdue.

Do not assume these are HFIR’s actual native status codes. Use configurable mappings from source values to these business labels.

Approval, execution, and overdue condition may overlap. Preserve separate fields for:

- Raw HFIR status.
- Execution status.
- Approval status.
- Due date.
- Overdue indicator.

For example, a successfully executed round may still await approval. Do not collapse these distinctions or fabricate approval.

Use source-provided overdue information where available. Only calculate overdue locally when a due date and agreed terminal-status rules are available, and label it as calculated.

Display:

- SAP work order number.
- HFIR round instance ID.
- Round template name and ID.
- Operator.
- Scheduled date.
- Due date.
- Completion timestamp.
- Execution status.
- Approval status.
- Overdue indicator.
- Raw source status.
- Last synchronization time.
- Rejection reason or comments, if supplied.

Link results using the SAP work order number carried in the HFIR result. Preserve leading zeros and avoid fuzzy matching.

Support multiple round instances per work order and display each separately.

Handle these cases explicitly:

- No HFIR result received: show “Awaiting HFIR data,” not “Incomplete.”
- Missing or unknown work order number: place the result in an unmatched-results queue for authorized review.
- Unknown source status: show “Unknown” and preserve the raw value.
- Failed synchronization: retain previously received data and show the error and last successful sync time.

Imports and synchronization must be idempotent. Preserve status history and use source timestamps, where available, to avoid replacing newer information with older updates.
